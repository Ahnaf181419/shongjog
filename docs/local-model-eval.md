### A.1 New test set — `eval/gen_test_set.jsonl`

76 queries, balanced across 5 hazards × 4 categories (plus 8 out_of_scope). Gold answers are **verbatim sentence spans** from the corpus chunk indicated by `retrieval_seed`; `expected_actions` and `must_mention` are literal `keywords_bn` entries of that chunk. `must_not_mention` is empty when the dangerous term already appears in the corpus (e.g. ব্লিচ in a "don't use bleach" chunk) — substring-match would false-positive on correct debunking; the judge covers those cases.

Schema:

```json
{"id":"G01","query":"...Bangla...","category":"standard","expected_topic":"ors",
 "gold_answer":"ORS তৈরির সহজ উপায়: ...। ৬ চা-চামচ চিনি ও আধা চা-চামচ লবণ ...",
 "expected_actions":["ORS","ওআরএস","ডায়রিয়া"],
 "must_mention":["পানিশূন্যতা","চিনি"],
 "must_not_mention":[],
 "retrieval_seed":["ors_recipe_basic"],
 "review_status":"pending_bn_review"}
```

### A.2 New harness — `eval/run_gen_eval.py`

- **Dart-parity retriever**: scoring mirrors `lib/rag/keyword_retriever.dart` line-for-line (tokenize regex, +1.0/`keywords_bn` ⊆ query, +0.5 topic ⊆ query, +0.1 per query token len>2 ⊆ chunk text).
- **Prompt fidelity guard**: regex-extracts `_kPersona`/`_kRules`/`_kEmergencyKeywords` from `lib/rag/prompt_builder.dart` at startup; `buildPrompt` and `isEmergencyQuery` mirror the Dart byte-for-byte. Drift triggers an error.
- **Post-processing**: `truncateAtTurnMarker` regex from `chat_repository.dart` (single alternation, case-insensitive).
- **Generation params**: temperature 0.3, top_k 40, top_p 0.95, max_tokens 256, seed cycles — mirror `lib/core/model_manager.dart`.
- **Optional embed mode**: `--embed-mode` switches retrieval to `sentence-transformers` + `litert-community/embeddinggemma-300m` (HF auth required, gated repo).
- **Metrics per query**: `bangla_fidelity` (U+0980–U+09FF ratio), `action_coverage` (NFC + Bangla↔ASCII digit mapping + lowercase), `forbidden_hit`, `latency_ms`, `approx_tokens`, `tps`.
- **Judge (unless `--no-judge`)**: Gemini 2.5 Pro via `google-generativeai`, strict single-line JSON, 2 retries; no key → warns, judge=None (imputed by category means).
- **Selftest**: `--selftest` runs the full pipeline with a deterministic stub model that returns `gold_answer + '\nUser: garbage\nAssistant: more'` — exercises truncation, schema validation, retrieval, scoring, jsonl+report+compare output. Prints `SELFTEST PASS` exit 0.
- **CLI exit codes**: 0 on selftest pass / successful runs, 1 on selftest failure, 2 on schema violation.

## Part B — EmbeddingGemma 300M retriever swap — IMPLEMENTED

### Surprise finding (resolved)

> `flutter_gemma` 1.3.2 (already our locked dep) exposes a full embedder API: `FlutterGemma.installEmbedder()` → `EmbeddingModel.generateEmbedding(text, taskType:)` with `TaskType.retrievalQuery` (prefix `task: search result | query: `) and `TaskType.retrievalDocument` (prefix `title: none | text: `). The `litert-community/embeddinggemma-300m` repo exists on HF (license-gated, `.tflite` not `.litertlm`). The plugin's `EmbeddingInstallationBuilder` accepts an HF auth token: `modelFromNetwork(url, token: hfToken)`.

This rewrote the old "no embedder API in 1.x" note in `docs/architecture.md` §2/§6.

### Vector-space trap (handled)

`assets/kb/vectors.bin` was built offline with `paraphrase-multilingual-mpnet-base-v2`. An EmbeddingGemma query vector is **not cosine-compatible** with an mpnet corpus vector — different models, different vector spaces. So the first time the retriever runs it re-embeds all 48 corpus chunks on-device (document task) and persists the result. Later launches load the cache in ~1 ms. Document text format mirrors `tools/build_kb.py` byte-for-byte:

```
Topic: {topic}. {text} {keywords joined}
```

### Risks (and mitigations)

| Risk | Mitigation |
|---|---|
| EmbeddingGemma HF repo is license-gated (`needsAuth: true`) | `install()` accepts a `hfToken`; until configured, `hasActiveEmbedder()` returns false and the app silently uses keyword retrieval — no behaviour change |
| Latency hit on first AI tap (embed + retrieve) | Warm the embedder at startup, mirroring `lib/main.dart` model warmup; corpus vectors persist to disk so subsequent launches are ~1 ms |
| Recall regression vs current 60-62% baseline | EmbeddingGemma on-device measurement is pending (Colab eval); the retriever gracefully falls back to keyword retrieval if the index is absent, fails, or returns empty hits above the floor |

## Assumptions

1. **A Bangla speaker is available for the ~1.5-day gold-answer curation pass.** The current set is extractive (verbatim from the corpus) and self-grounding — but every entry is marked `review_status: pending_bn_review` and should be re-read by a native speaker before the eval is run.
2. **Colab T4 free tier is sufficient** for 1.5-4B q4 inference. If T4 OOMs on Gemma 3 4B, fall back to A100 paid tier for that one model.
3. **Gemini 2.5 Pro free tier rate limits are tolerable** for the LLM-as-judge pass. ~456 judge calls (76 queries × 6 models) fits in one day's free quota.
4. **`EmbeddingGemma 300M` HF license-gating** is solved by the user supplying a token to `embedderService.install()`; until then the app behaves exactly as before (keyword retrieval).
5. **Existing `eval/run_eval.py` retriever code is reusable** as-is. The new harness extends (not replaces) it — keyword scoring is byte-parity with `lib/rag/keyword_retriever.dart` (the retrieval-only eval continues to use the mpnet cosine vectors in `tools/build_kb.py`).
