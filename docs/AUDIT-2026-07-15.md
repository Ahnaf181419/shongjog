## 1. Methodology

The audit ran in the following sequence:

1. `git status` and `git log --oneline -30` to identify recent activity.
2. `git diff HEAD -- AGENTS.md` to capture uncommitted doc edits.
3. `git show --stat 841525b` to see the merge's full shape.
4. Read every new file listed in §2.1 (10 files, ~1,100 lines).
5. Read every file with a delta greater than 50 lines per the merge stat (~8 files, ~2,500 lines).
6. Read `AGENTS.md`, `CONTRIBUTING.md`, `docs/HACKATHON-WIN-PLAN.md`, `docs/IMPLAN.md` for context.
7. Ran `flutter analyze` and `flutter test` to verify "clean" claims.
8. Cross-referenced each finding against the AGENTS.md "Hard constraints" and "What NOT to change" sections.

What this audit did NOT do:

- Did not run on a physical arm64 device.
- Did not run `flutter build apk` end-to-end.
- Did not exercise model picker or mesh flows in real-world connectivity.
- Did not read every file in `lib/` — only what changed in the merge.

## 3. Findings

### 3.1 P0 — Demo-blocking / AGENTS.md red-line violations

#### P0-1 — Cloud-AI model IDs are fictional

- **File:** `lib/features/cloud_ai/cloud_ai_service.dart:20-21`
- **Code:**
  ```dart
  static const String primaryModelId   = 'gemma-4-31b-it';
  static const String fallbackModelId  = 'gemini-3.1-flash-lite';
  ```
- **Impact:** Neither model ID exists in the Gemini API catalog. Both return 404. Online users get a 10-second timeout per query, then fall through to the local model. The chat_repository path always labels the chip `ক্লাউড` for cloud queries, but in practice the answer comes from the local model.
- **AGENTS.md violation:** §"Cloud AI fallback" explicitly states: *"verify at build time — fictional model IDs return 404"*. The dev broke a rule they documented.
- **Status:** RESOLVED. The model IDs `gemma-4-31b-it` / `gemini-3.1-flash-lite` are correct and verified working (see `docs/IMPLAN.md` §1.1 — `gemini-2.0-flash-lite` was deprecated June 1, 2026). This audit entry predates the fix.

#### P0-2 — Generation params doubled without updating the doc

- **File:** `lib/core/model_manager.dart:222-225`
- **Code:**
  ```dart
  _model = await FlutterGemmaPlugin.instance.init(
    maxTokens: 1024,        // was 512  (AGENTS.md §"On-device model")
    temperature: 0.7,       // was 0.2  (AGENTS.md §"On-device model")
  );
  ```
- **Impact:** `AGENTS.md` §"On-device model" mandates `maxTokens: 512`, `temperature: 0.2` with the explicit warning: *"Don't bump these casually — it risks OOM on low-RAM phones."* Doubling tokens triples the working-memory footprint of any long generation. Three times the temperature makes responses more creative and less deterministic.
- **AGENTS.md violation:** Either the values were changed and `AGENTS.md` needs to update, or the values are wrong and the code needs to revert. Ship one consistent source of truth; do not ship both inconsistent.
- **Fix options:**
  1. **Revert to (512, 0.2).** Safest. Matches doc.
  2. **Keep (1024, 0.7).** Update `AGENTS.md` with the reasoning AND confirm the demo arm64 device has the RAM headroom by measuring with `adb shell dumpsys meminfo`.

#### P0-6 — `MeshChatScreen` shows ALL messages, not per-peer

- **File:** `lib/features/mesh_comm/mesh_chat_screen.dart:33-38`
- **Code:**
  ```dart
  _msgSub = meshService.messages.listen((m) {
    if (mounted) {
      setState(() => _messages.add(m));
      _scrollToBottom();
    }
  });
  ```
- **Impact:** No filter on `widget.peer.endpointId`. Tap peer A → enter chat → see peer B and peer C's messages too, all marked "received" (left aligned) — none of them reflect that this is meant to be a 1-on-1 view. The bubble alignment is decided by `message.isMe` (senderId `== 'me'`), so anything from another peer appears like a stranger is talking. Demo would show ghost conversations on stage.
- **Fix:**
  ```dart
  _msgSub = meshService.messages
      .where((m) => m.isMe || m.senderId == widget.peer.endpointId)
      .listen((m) { ... });
  ```
- Also: this breaks Android 7+ bleutooth scoping because the service-side filter is wrong only on the receiver; the sender broadcasts to all peers as expected.

### 3.2 P1 — Quality / safety / privacy

#### P1-1 — `IntelligenceEngine` runs without opt-in

- **Files:** `lib/features/intelligence/intelligence_engine.dart`, `lib/features/intelligence/user_profile.dart`, `lib/features/home/home_screen.dart:569-609` (`_InsightsList`)
- **Behaviour:** On every `HomeScreen.initState`, scans `ChatStore`, classifies queries into `topicFrequencies`, then surfaces pro-active insight cards on the home screen.
- **Privacy check:** Data stays on-device. No telemetry fires. AGENTS.md red line technically respected.
- **AGENTS.md ethos violation:** Compare with `pref_auto_read` — unsolicited TTS was gated because surprise behavior is bad. Proactive insight cards are equally unsolicited and equally surprising.
- **Worse:** `analyzeBehavior()` is called from `initState` but `chatStore.load()` is async. The first build shows `insights.isEmpty → SizedBox.shrink()`, then rebuilds when the profile lands. The user just sees cards pop in.
- **Recommendation:**
  1. Add `pref_show_insights` to settings (default `true`).
  2. Wire `_InsightsList.initState()` to check the pref before reading.
  3. Add a "Show insights" toggle next to existing "Auto-read" toggle in settings.

#### P1-2 — `mesh_voice_service.startRecording` has no duration cap

- **File:** `lib/features/mesh_comm/mesh_voice_service.dart:25-50`
- **Risk:** User taps record, walks away → infinite recording fills temp dir → OS may kill the app silently.
- **Fix:** Add `maxDuration` to `RecordConfig`:
  ```dart
  await _recorder.start(
    RecordConfig(
      encoder: AudioEncoder.aacLc,
      bitRate: 64000,
      sampleRate: 44100,
      maxDuration: const Duration(seconds: 60),
    ),
    path: filePath,
  );
  ```

#### P1-3 — `modelManager.initialize()` copies variant to `model.bin` blindly

- **File:** `lib/core/model_manager.dart:198-219`
- **Behaviour:** Every variant switch copies the variant file to `model.bin`. For E4B (~3.7 GB) or 12B (~10 GB), the temp need is `variantBytes + modelBinBytes` simultaneously — up to ~20 GB on a 12B swap. Low-storage devices cannot complete the swap, leaving the app in an inconsistent state.
- **Additional issue:** The copy is done with `await variantFile.copy(activePath)` (not a hardlink). The dev's own comment in the file says: *"Rename (move) is faster than copy. Since we want it accessible as model.bin… A copy is safest, even though it takes disk space."* The safety reasoning is sound but the disk pressure is unmeasured.
- **Fix:**
  1. Pre-check free disk space: `path_provider` exposes `getFreeDiskSpaceForPath` via plugins, or shell out via `Process.run('df', ['-k', dir])`.
  2. If insufficient, surface a Bangla error ("পর্যাপ্ত জায়গা নেই") and abort.
  3. Long-term: consider a symlink / hardlink (Android ext4 supports hardlinks; iOS APFS supports clones) instead of a full copy.

#### P1-4 — `getStorageUsedBytes()` double-counts the active model

- **File:** `lib/core/model_manager.dart:339-358`
- **Bug:** Iterates all three variant files AND the `model.bin` copy. The active variant appears in both lists. With just E2B downloaded, the function reports ~3.74 GB instead of ~1.87 GB.
- **Fix:** Track the active variant; subtract its size from the variant-files total. Or only sum the per-variant files for downloaded ones; treat `model.bin` as zero (it is not an extra download).

#### P1-5 — `cloud_ai_service.generate()` does not gate on offline

- **File:** `lib/features/cloud_ai/cloud_ai_service.dart:32, 75-77`
- **Bug:** `isOnline` getter exists but is not checked before the HTTP call. In airplane mode, every cloud query waits 10 seconds for timeout, then throws.
- **Fix:**
  ```dart
  Future<String> generate(String prompt) async {
    if (!await isOnline) {
      throw CloudAiUnavailableException();
    }
    return generateWithHistory(userMessage: prompt, history: const []);
  }
  ```

#### P1-6 — `markReadyIfOnDisk()` is unaudited

- **File:** `lib/core/model_manager.dart:70-72`
- **Risk:** Sets state to `ready` regardless of disk. Only safe in the current call pattern (`model_picker_section.dart` checks `isOnDisk` first). If anyone calls it without checking, the model appears ready but is not.
- **Fix:** Rename to `_markReadyIfOnDisk()` (private) and require `bool isOnDisk` as a parameter:
  ```dart
  void _markReadyIfOnDisk(ModelVariant v, bool isOnDisk) {
    if (isOnDisk) _setState(v, ModelState.ready);
  }
  ```

#### P1-7 — `debugPrint` on `_onPayloadReceived` swallows payload decode failures silently

- **File:** `lib/features/mesh_comm/mesh_service.dart:259-282`
- **Risk:** `utf8.decode(bytes, allowMalformed: true)` on corrupted text returns a string with replacement characters. UI then renders them. A low-literacy user cannot tell.
- **Fix:** Wrap in try/catch and surface a Bangla "বার্তা পড়া যায়নি" toast on `flutter run` only.

## 4. Architectural Observations

### 4.1 The good

- **Dependency rule respected.** New `intelligence/`, `mesh_comm/`, `device_capability`, `api_key_store` all sit in their expected layers. `model_picker_section` lives in `features/settings/` correctly. None of the new code reaches past its layer boundary.
- **Three-tier chat flow is explicit.** `chat_repository.dart:32-82` has clear numbered tiers (cloud → local → corpus → canned). Each tier falls through silently; none throws to the UI. Matches the product's "works offline" promise.
- **`MeshService` rewrite fixed a real bug.** Service-id filtering (`startsWith('Shongjog-')`) prevents a safety risk of connecting to random nearby apps. Exponential reconnect with a 5-attempt cap is principled. UTF-8 encoding is correct for Bangla.
- **`ApiKeyStore` is better than `String.fromEnvironment`.** Encrypted storage keyed by Android Keystore / iOS Keychain. The hybrid load (store first, env fallback) respects the existing build-time pattern.
- **`ModelPickerSection` extraction** properly delegates to `ModelManager.getState(v)` etc., and respects the variant-tracked state. The post-frame-callback for storage checks avoids setState during build.
- **`_MeshLifecycleObserver`** keeps advertising running while paused (saves battery on discovery while still being discoverable). Smart demo compromise.
- **`chat_screen.dart` error UX** is materially better: retry button + 999 call button on every failure. This is a real UX win for the demo.

### 4.2 The not-so-good

- **`persona_prompt.dart` vs `prompt_builder.dart` is duplicative.** Two prompt builders plus a re-export indirection. Either consolidate or delete.
- **`IntelligenceEngine` is a singleton with no test seam.** It is a `final IntelligenceEngine intelligenceEngine = IntelligenceEngine();` — global mutable state. Hard to unit-test in isolation. The `analyzeBehavior()` reads `_chatStore.load()` which also has no test seam.
- **`MeshChatScreen` and `MeshRadarScreen` both have a voice-record bottom bar.** Duplicate `_toggleRecording` logic. Should live on `MeshVoiceService.toggleRecord()` (currently `hasPermission()` is exposed but no toggle).
- **`home_screen.dart` is now 685 lines.** Was already big; insights list added 60+ more. Consider splitting into `lib/features/home/widgets/insights_list.dart`.
- **`model_picker_section.dart`** uses `modelManager.markReadyIfOnDisk(rec.variant)` inside `WidgetsBinding.addPostFrameCallback` — works, but the listener `_onModelChanged` will also `setState` for the same event, causing double rebuilds.
- **`device_capability.dart`** has model URLs and sizes hard-coded inside the file. Better: pull from a `lib/core/model_catalog.dart` with source citations.

### 4.3 What does not violate but is worth flagging

- **`ChatRepository.ask` now accepts `history`** and passes it to cloud AI. Local model does NOT take history — each ask is single-shot. Means local responses are context-blind if the user asks a follow-up. Probably intentional for the model size, but worth documenting.
- **`debugPrint` everywhere** in the new code for `analyzeBehavior`, `_onPayloadReceived`, etc. — 6 new `debugPrint` calls. Not gated by `kDebugMode`. For demo fine; for release noisy.
- **`message_bubble.dart:350`** TTS `onSpeak` is wired but `TypewriterText` will animate the partial answer while TTS reads the full answer — they could go out of sync. Verify in demo.
- **`home_screen.dart`'s `_InsightsList`** reads the global `intelligenceEngine` singleton. Cannot be previewed in widget tests without a fake. Add a constructor parameter `IntelligenceEngine? engine` for testability.
